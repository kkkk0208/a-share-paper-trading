# 实时行情采集

采集进程只记录行情，不下单。交易时段每 3 秒向腾讯发一次合并请求，腾讯没返回的标的再问新浪。每条快照先检查，合格的存进 `market_snapshots`，不合格的和接口故障写进 `quote_events`。不估算、不补值、不用旧值顶替。

免费接口能拿到的是交易所约每 3 秒一次的 Level 1 快照（五档）。腾讯和新浪都是非官方接口，没有服务保证，可能限流或改格式。

## 一次性准备

1. 指定 Python（只需一次，之后新开的终端生效）：`setx A_SHARE_PYTHON "C:\path\to\python.exe"`。不设置时依次使用项目里的 `.venv`、PATH 上的 `python`。
2. 下载交易日历：`.\scripts\quote_collector.ps1 sync-calendar`。生成 `data/trade_dates.csv`，包含当年剩余的交易日。需要 akshare（`requirements-backtesting.txt`）。每年 12 月交易所公布下一年休市安排后再运行一次。

2026-10-14 已在 Windows 实机同步成功：共 8,797 个交易日，范围为 1990-12-19 至 2026-12-31。抽查 2026-01-01、春节 2 月 16 日至 20 日、国庆 10 月 1 日至 7 日均不在日历，10 月 8 日、10 月 9 日和 10 月 14 日在日历。文件属于本机运行数据，由 `.gitignore` 排除，不提交到仓库。

交易风控现在用这个文件判断是否交易日。日期超出文件范围时 fail closed，并提示重新运行 `sync-calendar`。`data/trading_calendar.csv` 仍只用于净值快照的基准收盘价。

## 每天运行

```powershell
.\scripts\quote_collector.ps1 run
```

开盘前启动即可：9:15 之前等待，9:15 到 11:30、13:00 到 15:05 采集，收盘后自动退出；周末和休市日直接退出。标的取 `config/paper_trading.json` 里的白名单和基准，可用 `--extra-symbol 600000.SH` 追加，或用 `--symbol` 完全指定。

本机已注册 Windows 计划任务 `AShareQuoteCollector`：工作日 9:05 运行，允许电池供电、唤醒电脑并在错过启动时间后补跑，重复实例会被忽略。任务为两个行情域名设置 `NO_PROXY`，日志追加到 `runtime/paper_trading/collector.log`。2026-10-14 收盘后手动触发的退出码为 0，下一次计划运行时间为 2026-10-15 09:05。

剩余样本和每日报告的可复现设置：

```powershell
.\scripts\schedule_quote_acceptance.ps1 -SampleDate 2026-10-15
```

此脚本注册三个一次性样本任务（指定日期 9:20、10:00、14:58，标的为 002195.SZ、002815.SZ、000300.SH），以及工作日 15:10 的 `AShareQuoteQualityReport`。样本任务不会补跑错过的时段；日期/阶段校验也会拒绝手动误触发。报告写入 `runtime/paper_trading/reports/YYYY-MM-DD.json`，日志分别为 `runtime/paper_trading/acceptance-<phase>.log` 和 `acceptance-report.log`。所有任务使用当前用户的交互式登录，必须保持 Windows 登录且接通电源；锁屏可运行，注销后不会运行。脚本支持 `-WhatIf` 预览和 `-PythonPath` 显式指定解释器，也会读取已保存的用户 `A_SHARE_PYTHON`，注册前检查 Python 能启动。

2026-10-14 实机验证：误触发次日样本任务得到退出码 2，未产生错标样本；报告任务生成 UTF-8 JSON，并因当天未录制完整行情返回质量不通过（退出码 2）。这代表报告流程已跑通，不代表行情验收通过。需连续 3 至 5 个交易日按覆盖率、间隔、时延和双源差异逐项验收。

本聊天还安排了 5 个工作日的 Codex 跟进（北京时间 9:35、15:35），检查采集、用独立测试账本走查流程、审查原始样本并汇总验收结果。此跟进需要 Codex 保持运行；Windows 采样/报告任务则依赖当前用户保持登录。正式模拟账户的批准规则不变，任务 7 的权限设计仍待用户决定。

其它命令：

- `once`：马上采集一轮，不看时段，用来检查网络和解析。加 `--dry-run` 不写数据库。
- `report --date 2026-10-15 --out runtime\paper_trading\reports\2026-10-15.json`：当天数据质量报告，`--out` 可选。全部通过时退出码为 0，否则为 2。
- `capture --symbols 002195.SZ 000300.SH --label continuous`：保存两个源的原始返回到 `tests/fixtures/quotes/real/`，供解析测试使用。

定时采样可加 `--expected-date 2026-10-15 --expected-phase opening_call`。实际日期或交易阶段不符合时，采样直接返回退出码 2，不请求接口、不写入错标样本。任一源抓取失败也返回 2，原始错误仍保存在样本元数据中，便于任务调度器识别失败。

## 和交易的关系

- CLI 和看板默认先读采集进程存下的最新快照（6 秒以内），没有才去网上实时抓。采集进程开着时，交易和录制用的是同一份数据。
- 涨停时卖盘为空、跌停时买盘为空，现在都是正常行情：涨停可以卖，跌停可以买；对面没有挂单的一侧会被风控拒绝并说明原因。
- 14:57 到 15:00 是收盘集合竞价，不再算作连续竞价。
- 看板里的实时抓取连续失败 3 次切到新浪，之后每 60 秒重试腾讯，恢复后切回。采集进程则是每一轮都先问腾讯，缺的再问新浪。新浪没有涨跌停价，使用当天从腾讯记下的值（`daily_limits` 表，标记 `cached_limits`）。当天没有记录时保持缺失，风控照样拒绝。

## 数据存在哪里

都在 `runtime/paper_trading/paper_trading.sqlite3`：

| 表 | 内容 |
| --- | --- |
| `market_snapshots` | 合格快照。`payload_json.collector` 里有来源、时段、质量标记、昨收、成交量等；每只股票每天第一条和有警告的快照保留原始返回 |
| `quote_events` | 被拒快照、接口错误与恢复、断流与恢复、涨跌停状态变化、两个源的价格核对 |
| `daily_limits` | 每只股票每天的涨跌停价，第一次看到的值为准 |
| `collector_status` | 采集进程最近一轮的状态 |

三只标的录一天大约 15 MB。

## 质量标记

| 标记 | 级别 | 含义 |
| --- | --- | --- |
| `not_today` | 拒收 | 行情日期不是今天（停牌或开盘前的旧数据） |
| `non_monotonic` | 拒收 | 时间比上一条早（常见于切换来源时） |
| `crossed_book` | 拒收 | 连续竞价时买一高于卖一 |
| `price_outside_limits` | 拒收 | 最新价超出涨跌停价 |
| `stale` | 警告 | 行情比本机时间旧 30 秒以上 |
| `clock_skew` | 警告 | 行情时间比本机时间晚 3 秒以上，说明电脑时钟慢了 |
| `locked_book` | 警告 | 连续竞价时买一等于卖一 |
| `one_sided_book` | 警告 | 一侧为空，但不在涨跌停价 |
| `missing_limits` | 警告 | 没有涨跌停价，交易会被拒绝 |
| `large_jump` | 警告 | 和上一条相比变动超过 5% |
| `limit_up_sealed` / `limit_down_sealed` | 信息 | 涨停或跌停封板 |
| `no_book` | 信息 | 两侧都为空 |
| `cached_limits` | 信息 | 涨跌停价来自当天缓存 |

## 还需要用真实数据确认

解析按通常的字段位置写成（腾讯 `~` 分隔：3 最新价、9 到 18 买盘、19 到 28 卖盘、30 时间、47 涨停价、48 跌停价，盘口单位为手；新浪 `,` 分隔：盘口单位为股、30 和 31 为日期时间、32 为状态）。停牌股、集合竞价时的盘口、指数行情的具体样子都需要用 `capture` 抓真实样本确认，`tests/test_real_quote_samples.py` 会自动检查。

2026-10-14 收盘后已用 600601 简报长期使用的本机 `tencent_quote.py` 核对腾讯字段。最新价、昨收、今开、五档、时间、高低、成交额、涨停价和跌停价均与仓库常量一致。当天 002195.SZ 和 002815.SZ 的字段 6 与字段 36 分别同时为 `696223`、`692875`，两处都是累计成交量（手）；采集层读取字段 6 并换算为股。请求均使用 `qt.gtimg.cn/q=`、浏览器 User-Agent 和 GBK 解码。腾讯下载先尝试 HTTPS；若端点主动断开 TLS，才回退 HTTP。HTTP 返回仍必须通过解析、时效、质量和双源核对，不能直接驱动交易。

本机 Windows 代理指向 `127.0.0.1:10801`，该代理访问行情端点时有 TLS EOF/超时。采样时用 `NO_PROXY=qt.gtimg.cn,hq.sinajs.cn` 直连后，两个源均成功；计划任务也会显式绕过这两个行情域名，其余网络仍沿用系统代理。

2026-10-14 已保存三组收盘后真实样本：002195.SZ、002815.SZ 与沪深 300 的普通收盘快照；600202.SH（哈空调）的涨停封板快照，腾讯盘口有买盘、卖盘为空且最新价等于涨停价；002717.SZ（*ST 岭南）的停牌快照，双源盘口均为空，腾讯字段 40（从 0 起计）为 `S`，新浪状态为 `03`。腾讯 `S` 直接解析为 `suspended`，即使出现盘口也不可交易；其它未识别的状态保持 `unknown`。新浪停牌行把最新价写为 0，解析器保留昨收作为只读参考价并明确标为不可交易。集合竞价和连续竞价样本待下一交易时段补采。

电脑时钟要开自动同步：现有规则下，时钟慢 2 秒以上或快 10 秒以上，所有行情都会被判为过期。`report` 里的 `latency_seconds` 可以看出时钟偏差。2026-10-14 用 `time.windows.com` 连测 5 次，偏差为 0.87 至 0.92 秒；但 Windows Time 服务当前为“手动/已停止”，普通用户权限无法启动或强制同步，仍建议用管理员权限启用自动对时。交流供电的睡眠超时为“从不”，电池供电为 30 分钟；采集日必须保持接通电源，否则进程可能在盘中因系统睡眠中断。
