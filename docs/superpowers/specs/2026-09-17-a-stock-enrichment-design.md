# A 股持仓日报数据增强设计

## 目标

在现有 `600601` 自动化的腾讯行情与 AKShare 主链之外，为 `002195 岩山科技` 和 `002815 崇达技术` 增加三类可追溯信息：近期公告、估值及历史位置、融资融券/解禁/大宗交易风险。增强接口失败时保留现有日报能力，不用旧值或推测值冒充本次数据。

## 现状与约束

- 每次自动化必须继续通过 `run_600601_automation.ps1` 启动专用 Python、生成 HTML/PDF，并运行 `test_600601_outputs.ps1`。
- 腾讯实时行情、腾讯历史 K 线、AKShare 市场宽度、资金流、涨停池和申万行业链保持现状。
- `a-stock-data` 当前主行情源 mootdx 存在公开的失效报告，因此不接管现有行情或 K 线。
- 不把完整的约 232 KB `SKILL.md` 注入自动化提示词，也不在运行时执行远端 Markdown 中的代码。
- 新数据必须带来源日期、抓取时间和来源名称；空结果与接口失败必须分开表达。

## 方案比较

### 方案 A：把完整 skill 加入自动化提示词

优点是接入最快。缺点是提示词显著膨胀，内嵌代码会与“固定 runner 为唯一入口”的现有规则冲突，也难以测试和固定版本。拒绝采用。

### 方案 B：复制 skill 的全部端点到项目

可以离线审查，但会引入大量未使用依赖和易失接口，扩大每日自动化的故障面。拒绝采用。

### 方案 C：抽取少量端点，封装为本地增强模块

仅实现日报需要的能力，保留原始响应、统一校验和缓存，并通过明确的数据结构交给报告生成器。接口失败不影响主报告生成。采用此方案。

新增 `a_stock_enrichment.py`，负责数据获取、字段校验、日期校验、缓存与统一返回结构。`generate_600601_report.py` 只调用模块的聚合入口，并把结果传给文本、HTML 和 PDF 渲染；不直接散落新的网络请求。

## 第一阶段能力

### 申万一级行业成分三级降级

- 现有 `ak.index_component_sw()` 保持主源；成功时校验字段，并把指数代码、成分、官方权重和获取日期写入本地缓存。
- 主源连接异常或字段漂移时，优先读取最近 30 天的成功缓存，并在报告中标注缓存日期。
- 无可用缓存时，使用 `a-stock-data` 的申万行业变迁史重建当前成分；`801xxx` 指数代码与分类一级代码的映射只从成功主源样本推导并持久化，不凭名称猜测。
- skill 官方 XLS 在当前 Python 证书包下校验失败、但 Windows 系统信任链可访问；适配器使用 `truststore` 接入系统证书，不关闭 TLS 校验。
- 分类历史不含官方指数权重。重建成分时按腾讯流通市值计算代理权重，并明确标注 `estimated_float_cap_weight`，不得显示为官方权重。
- 主源、缓存和分类重建均不可用时，仅该行业降级，不阻断其他行业或日报生成。

### 近期公告

- 查询两只持仓最近 7 个自然日公告。
- 输出公告日期、标题、类别和原文链接。
- 最多展示每只 5 条，优先风险提示、业绩、股东变动、重大合同和监管事项。
- 接口成功且无公告时显示“近 7 日无公告”；接口异常时显示“公告接口暂不可用”。

### 估值及历史位置

- 当期估值优先复用已稳定的腾讯字段；历史 PE/PB 使用 baostock 数据计算分位。
- 至少需要 120 个有效交易日才输出历史分位，样本不足时明确标注。
- PE/PB 非正值不参与分位计算；不得把亏损公司的负 PE 当成低估。
- 历史数据按日缓存，同一交易日不重复下载。

### 杠杆和事件风险

- 融资融券展示最新披露日、融资余额及近 5 个披露日变化。
- 解禁展示未来 90 天事件、可流通数量及占比；无事件与接口失败分开处理。
- 大宗交易展示最近 30 天笔数、成交金额和平均溢折价；只在有完整价格字段时计算溢折价。

## 数据源策略

- 优先采用交易所、巨潮等官方来源；需使用东方财富端点时执行串行限流、超时、有限重试和字段校验。
- 不使用 mootdx 作为本功能依赖。
- 固定参考 `a-stock-data` 提交 `2012ce7cd0e75d379c5e6cbd3115514f300f3bc8`，不在自动化运行时从 GitHub 拉取最新代码。
- 所有网络函数支持注入请求函数，以便测试时不访问公网。

## 错误处理与状态

- 增强模块捕获每个端点的异常，记录 `source`、`code`、异常类型和简短原因。
- 第一阶段增强错误不加入现有 `market["errors"]`，避免改变当前 `STATUS=OK` 门槛；报告新增“增强数据状态”区块。
- 不读取超过交易日期的缓存，不回退到未标注日期的历史结果。
- 如果代码、交易所或返回证券名称不匹配，丢弃该响应并记录校验错误。

## 报告改动

- 文本、HTML 和 PDF 增加“公告、估值与事件风险”章节。
- 每只持仓使用同一顺序：公告 → 估值 → 融资融券 → 解禁 → 大宗交易。
- HTML 保持现有批准的自包含看板样式，新增一个全宽面板，不引入 CDN 或 JavaScript。
- 来源区增加增强数据源与抓取日期。

## 测试设计

- 新增 Python 单元测试，使用固定响应验证正常、空数据、字段漂移、证券代码不匹配、过期缓存和网络失败。
- 测试 PE/PB 分位的非正值过滤和最小样本要求。
- 测试增强接口全部失败时，原报告仍可渲染且状态不被错误降级。
- 扩展 `test_600601_outputs.ps1`，验证文本和 HTML 包含新章节、两只当前持仓且不出现旧标的。
- 保留并运行现有完整 runner 回归测试；联网端点只用于最终冒烟测试，单元测试不依赖网络。

## 不在本阶段处理

- 不增加模拟账户下单或撮合功能。
- 不改变持仓筛选、次日倾向或综合评分公式。
- 不接入研报、互动易、筹码分布和 ETF 期权。
- 不清理自动化提示词中的历史乱码；该问题另行处理。

## 验收标准

1. 固定测试数据下的新增 Python 单元测试全部通过。
2. 增强数据全部失败时，现有报告仍能生成 HTML/PDF，并明确标注暂缺。
3. 成功返回时，文本、HTML 和 PDF 对公告、估值与事件风险的数值和日期一致。
4. 原始增强 JSON 可追溯到报告展示内容。
5. 现有 `test_600601_outputs.ps1` 与完整 runner 均通过。
6. 申万成分主源失败时能够读取成功缓存；无缓存且存在已验证代码映射时能够从分类历史重建成分，并标注估算权重。
