# 独立策略回测

这套回测用于检验明确、可复现的交易规则。当前附带的 `ma_cross_v1` 只是演示框架的示例策略，不是从现有简报中推导出的“真实策略”，它的结果也不能证明未来有效。

## 它解决什么问题

- 信号只读取当日收盘数据，最早在下一个交易日开盘成交，避免偷看未来数据。
- 模拟 A 股 100 股整手、T+1、滑点、成交量参与上限、最低佣金、印花税和过户费。
- 按时间顺序切分训练集、验证集、测试集，不随机打乱时间序列。
- 同时记录沪深 300 基准，输出累计收益、年化收益、最大回撤、波动率、夏普、胜率、盈亏比和超额收益。
- 每次运行保存配置、数据文件哈希、逐笔成交和每日权益，方便复查和复现。
- 下载沪深 300 时同步生成 `data/trading_calendar.csv`，并把股票不复权收盘价另存到 `data/paper_closes/`，供模拟盘补快照；不会拿前复权价格回填真实现金账本。

## 使用

在项目目录运行：

```powershell
.\scripts\backtest.ps1 download
.\scripts\backtest.ps1 run --output-dir runtime\backtesting\runs\ma-cross-demo
```

默认配置在 `config/backtest.example.json`。第一条命令通过 AKShare 下载股票和沪深 300 日线并保存为本地 CSV；第二条命令只读取这些本地文件，不会在回测过程中悄悄替换数据。如果公开数据接口暂时不可达，下载会直接失败，不会用过期缓存伪装成新数据。

运行产物：

- `summary.json`：全样本及训练、验证、测试三个时段的指标。
- `equity_curve.csv`：每日现金、持仓市值、组合权益和基准权益。
- `trades.csv`：信号日、实际成交日、开盘价、滑点后成交价、费用和已实现盈亏。
- `run_manifest.json`：完整配置、时序约束和输入 CSV 的 SHA-256。

清单还会记录每个输入文件的下载时间。前复权价格会在后续分红送转发生后整体重算，因此相同日期区间在半年后重新下载不一定相同；CSV 哈希和下载时间共同定义一次可复现运行。

## 重要口径

默认使用前复权日线。它适合研究信号连续性，但不是逐笔成交数据，也不能精确重建真实账户在分红送转时的现金流。要做更严格的现金账本回测，应改用不复权行情并单独接入公司行动数据。

当前框架不模拟集合竞价、盘口冲击和真实排队。日线成交量参与上限只是一种保守约束，不代表真实可成交性。

回测会根据前收盘和板块常规涨停比例计算涨停价；买入日开盘价达到涨停价时跳过该笔买入，避免把明显无法排到的涨停开盘当成必然成交。该规则仍无法识别历史 ST 状态，也不能替代逐笔盘口。

股票日期相对沪深 300 交易日历连续缺失达到 `execution.suspension_warning_days`（默认 5 日）时，结果会输出停牌／数据缺口警告。均线仍按有效交易记录计算，使用结果前必须确认缺口原因。

少于 60 个交易日的全样本或分段不会输出年化收益、年化波动率和夏普，只保留累计收益、回撤及交易统计。费用费率统一维护在 `config/fees.json`，不再在模拟盘和回测配置中各存一份。

## 把示例换成你的策略

需要先把策略写成没有歧义的规则：每个输入字段、观察时点、买入条件、卖出条件、仓位大小和调仓频率都必须固定。然后在 `backtesting/strategy.py` 中新增策略并在配置里显式选择。参数只能在训练集调试，在验证集做选择，测试集只在最终方案固定后查看一次；反复查看测试集再改规则会造成样本外泄漏。
